UX-001 Update: Fix false positive unsaved changes detection - COMPLETED

Fixed bug where unsaved changes warning could appear incorrectly when:
- Opening existing invoice and leaving without making changes
- Opening new invoice and leaving after initial data loading

Root cause: useUnsavedChanges hook was initialized with initial state before async data loading completed. When data loaded via useEffect, the ref was updated but hook's internal savedFingerprint was stale.

- Call resetTracking(snapshot) after setting initialRef in data loading effects
- Move useUnsavedChanges hook call BEFORE the useEffects that call resetTracking
